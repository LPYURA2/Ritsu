# Рицу · Android

Самостоятельный Android-клиент для существующей Рицу. Первый этап — локальный демонстрационный интерфейс на Kotlin и Jetpack Compose с шестью экранами и анимированным 2D-аватаром.

Фактические результаты проверки, параметры APK и состав поставки: [docs/DELIVERY.md](docs/DELIVERY.md).

**Рабочее ядро не подключено.** Приложение не читает `~/ritsu-bot/ritsu_termux_kit`, Telegram, базы памяти или рабочие конфигурации. Демонстрационный источник возвращает подготовленные данные и ответы; модели ИИ, отдельной личности и новой памяти Рицу здесь нет.

## Что доступно

| Экран | Возможности первого этапа |
| --- | --- |
| Главная | Авторский временный 2D-аватар с длинными волосами, эмоция и занятие из состояния демонстрационного источника |
| Диалог | Текстовый диалог с подготовленными ответами; место для будущего голосового режима |
| Цели и занятия | Демонстрационные цели, интересы, прогресс и ограниченные действия |
| Разрешения | STOP, пауза, явное возобновление, временные полномочия с лимитом действий |
| История деятельности | Журнал событий, решений и отклонённых запросов демонстрации |
| Система | Режим подключения и диагностика; пояснение границ будущей интеграции и резервирования |

STOP и пауза воздействуют только на демонстрационный источник в приложении. Они не останавливают существующую Рицу в Termux. Проверка разрешений находится за интерфейсом `CoreGateway`: запрос, отправленный в обход экрана, также должен пройти проверку источника.

## Сборка

Требуются Android Studio с поддержкой Android Gradle Plugin 8.9.1, JDK 17 или 21, Android SDK Platform 35 и доступ к Google Maven, Maven Central и дистрибутиву Gradle. Минимальная версия Android — 11, API 30.

1. Откройте каталог проекта в Android Studio и дождитесь Gradle Sync.
2. Установите SDK Platform 35 и требуемые Build Tools через SDK Manager.
3. Укажите SDK через `ANDROID_HOME` или локальный файл `local.properties`:

   ```properties
   sdk.dir=/absolute/path/to/Android/Sdk
   ```

   `local.properties` не входит в исходники.
4. Выполните из корня проекта:

   ```bash
   ./gradlew test :app:assembleDebug lintDebug
   ```

На Windows используйте `gradlew.bat`. APK стандартной сборки находится в `app/build/outputs/apk/debug/app-debug.apk`.

Для UI-тестов требуется запущенный Android-эмулятор либо подключённое устройство API 30+:

```bash
./gradlew :app:connectedDebugAndroidTest
```

Зафиксированные версии: Gradle 8.11.1, AGP 8.9.1, Kotlin 2.1.10, Compose BOM 2025.02.00, `compileSdk`/`targetSdk` 35. JVM-байткод — 17.

## Проверка вручную

1. Запустите приложение. Убедитесь, что режим демонстрации явно обозначен. Откройте все шесть разделов и вернитесь на главный экран.
2. Проверьте мимику, моргание и движение волос аватара. Пауза и STOP должны менять его состояние; после возобновления отображается актуальное состояние источника.
3. В диалоге отправьте текст. Ответ должен быть обозначен как демонстрационный. Голосовой режим не должен запрашивать доступ к микрофону.
4. Попробуйте действие с целью без полномочия. Проверьте отказ и запись в истории. Выдайте временное полномочие и повторите действие; счётчик доступных действий должен уменьшиться.
5. Исчерпайте лимит либо дождитесь окончания полномочия. Повторное действие должно быть отклонено. Отзовите полномочие вручную и проверьте тот же результат.
6. Включите паузу. Проверьте блокировку действий и запись в журнале. Явно возобновите демонстрацию.
7. Нажмите STOP. Проверьте блокировку действий, отзыв полномочий и запись в журнале. После подтверждённого успешного сохранения закройте и заново откройте приложение: STOP должен сохраняться. При ошибке записи STOP блокирует текущий процесс, но его сохранение до следующего запуска не гарантируется; подробности — в `docs/SECURITY.md`. Возобновите работу отдельным явным действием; старые полномочия не должны восстановиться.
8. На экране системы убедитесь, что подключение рабочего ядра отсутствует и приложение не предлагает выполнять команды Termux.

Автоматические проверки безопасности расположены в модуле `core`; Android UI-проверки — в `app/src/androidTest`. Наличие исходников теста не означает его выполнение: фактические результаты текущей среды следует смотреть в отчёте поставки и каталогах `build/reports` после запуска команд.

## Устройство проекта

- `app/` — Android-приложение, Compose, навигация, отрисовка аватара и Android-адаптеры хранения.
- `core/` — независимый от Android контракт ядра, демонстрационный источник и проверки безопасности.
- `docs/ARCHITECTURE.md` — границы модулей и состояние приложения.
- `docs/SECURITY.md` — STOP, временные полномочия и ограничения демонстрации.
- `docs/INTEGRATION.md` — проект будущего соединения с единственным ядром Рицу.
- `docs/ASSETS.md` — происхождение временной графики.
- `third_party/material-icons/` — происхождение и Apache 2.0 для 14 выбранных официальных Material-иконок; остальные иконки предоставляет `material-icons-core`.

Дальнейшее подключение к существующему ядру, голосовой режим, окончательный дизайн персонажа и работа с резервными копиями — отдельные этапы, требующие отдельного согласования. В текущем проекте эти интеграции не активированы.
